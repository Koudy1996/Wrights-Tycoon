## 5. Refactor execution order

Run work in this order to reduce breakage:

1. `M1.Core`: finalize unified aircraft physics, ISA constants, thrust model (jet + piston -> `Thrust (T)`).
2. `M2.EngineDesigner`: keep existing behavior, move remaining tunables to `balance`.
3. `M3.PlaneDesigner`: treat as source of truth for aircraft type logic (M4 merged into M3).
4. `M5.Factory` and `M6.Contracts`: keep behavior, externalize remaining constants.
5. `M8.UI`: only update bindings/references after module APIs are stable.

## 6. Mandatory rule checks before coding

1. Keep player-facing inputs unchanged.
2. Keep UI behavior unchanged.
3. Ignore aircraft type development cost and MD in gameplay calculations.
4. Ensure all calculation code is deterministic and Unity-independent.
5. Keep dependency direction: `M8.UI -> Modules -> balance`.

## 7. Acceptance checklist

Before closing the task, verify:

1. Max speed at 0/5000/10000 m uses ISA densities from `balance`.
2. Cruise speed solves `Lift = Maximum weight`.
3. Cruise fuel burn scales linearly with thrust ratio.
4. Range uses `Fuel / CruiseBurn * CruiseSpeed`.
5. Empty, wet, maximum, useful weights match specified formulas.
6. `CD`, aircraft length, frontal area, maneuverability all use tunable coefficients in `balance`.
7. Piston and jet engines both expose unified `Thrust (T)`.
8. UI compiles without direct physics/balance logic embedded in UI scripts.
